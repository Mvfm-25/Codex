## 1. O que um compilador faz
1. **Entrada** : programa-fonte (uma cadeia de caracteres).
2. **Fases de análise** (front-end) — cada uma usa um formalismo diferente :

| Fase | Pergunta que responde | Formalismo | Reconhecedor |
|---|---|---|---|
| Léxica | "Estes caracteres formam palavras válidas?" | Expressões regulares / gramáticas regulares | Autômato finito (AFD) |
| Sintática | "Estas palavras estão na ordem certa?" | Gramáticas livres de contexto | Autômato de pilha |
| Semântica | "Isto faz sentido?" (tipos, declarações) | Gramáticas de atributos + tabela de símbolos | Ações semânticas |

3. **Fases de síntese** (back-end) : código intermediário → otimização → geração de código. *(Assunto da [P3](./P3.md).)*

## 2. Revisão de Linguagens Formais — passo a passo
### 2.1 Os quatro conceitos de base
- **Alfabeto** : conjunto *finito* de símbolos. Ex.: `{0,1}`, ASCII.
- **Sentença** : sequência finita de símbolos do alfabeto (não precisa ser "válida").
- **Linguagem** : conjunto de sentenças (pode ser infinito).
- **Gramática** $G = (N, T, P, S)$ : não-terminais, terminais, produções, símbolo inicial. Serve para **definir** quais sentenças são válidas.
	- $L(G) = \{ p \mid S \Rightarrow^* p \}$ — a linguagem é tudo que $S$ deriva em 0 ou mais passos.
	- O **analisador sintático** é exatamente o programa que verifica se $p \in L(G)$.

### 2.2 Hierarquia de Chomsky (o que importa pra cadeira)
| Gramática | Forma das produções | Reconhecedor | Uso |
|---|---|---|---|
| Regular (tipo 3) | `A → a` , `A → a B` | Autômato finito | **Léxico** |
| Livre de contexto (tipo 2) | `A → α` (um NT à esquerda) | Autômato de pilha | **Sintático** |
| Sensível ao contexto / irrestrita | — | Máquina de Turing | "inúteis para compiladores" |

> **Por que o léxico não basta?** Um AFD tem estados finitos: não consegue "contar" quantos `{` abriram para exigir o mesmo número de `}`. Isso exige **pilha** → GLC.

### 2.3 Derivação, árvore & ambiguidade
- **Derivação** : trocar um não-terminal pelo lado direito de uma de suas produções.
	- **Mais à esquerda (lm)** : sempre o NT mais à esquerda. **Mais à direita (rm)** : sempre o mais à direita.
- **Árvore de derivação** : representação gráfica — raiz = $S$, filhos de um nó = lado direito da produção usada. *Não guarda a ordem* (lm/rm).
- **Ambígua** : existe **mais de uma árvore** para a mesma sentença. Problema: cada árvore dá um **significado** diferente (ex.: `else` pendente).

### 2.4 Receita: precedência & associatividade na gramática
1. **Um não-terminal por nível de precedência** — maior precedência fica **mais abaixo** (perto das folhas).
2. **Associatividade** sai do tipo de recursão :
	- recursão à **esquerda** (`E → E + T`) → associativo à **esquerda**;
	- recursão à **direita** (`T → F ^ T`) → associativo à **direita**;
	- **sem recursão** (`R → E > E | E`) → **não associativo** (Java rejeita `a > b > c`).
```code
E → E + T | E - T | T        // nível mais baixo: + e -
T → T * F | T / F | F        // * e / ligam mais forte
F → ( E ) | numero | ident   // folhas
```

## 3. Análise Léxica — passo a passo
### 3.1 O que o analisador léxico faz
```code
entrada : if ( x == 3 ) ...
saída   : IF LPAR IDENT EQ NUMBER RPAR ... EOF
```
1. Devolve **tokens** (símbolos terminais) — a cadeia **sempre termina com EOF**.
2. **Descarta** o que não tem significado : espaços, tabs, CR/LF, comentários.
3. Por que separado do sintático? Distinguir `if` de um identificador e ignorar brancos em qualquer ponto bagunçaria a gramática inteira. Tokens são **regulares** → reconhecidos por AFD, mais rápido.

### 3.2 Expressões regulares
| ER | Significado |
|---|---|
| `αβ` | concatenação |
| `α \| β` | alternativa |
| `α*` | zero ou mais |
| `α+` | um ou mais |
| `α?` | opcional |
| `[a-z]` | conjunto de caracteres ; `[^"]` = qualquer um **exceto** `"` |
| `.` | qualquer caractere exceto `\n` |

Exemplos clássicos (da [Solução de atividades](../atividades/SolucaoDeAtividades.pdf)) :
- identificador : `[a-zA-Z][a-zA-Z0-9_]*`
- inteiro sem sinal : `[0-9]+`
- notação científica : `[0-9]+[Ee](\+|\-)?[0-9]+`
- string JSON : `\"[^\"]*\"` · número JSON : `[0-9]+(\.[0-9]+)?`

### 3.3 Autômatos finitos
- **AFD** = $(S, I, \delta, s_0, F)$. Reconhece se, ao fim da entrada (ou quando não há transição), está num estado final.
- **ER ↔ AF** : a ER **gera** (descreve) a linguagem; o AF a **reconhece**. São equivalentes.
- **Gramática regular → AF** : cada NT vira um estado; `A = b C` vira `A --b--> C`; `A = d` vira `A --d--> stop`.
- **AFND → AFD** : construção de subconjuntos (cada estado do AFD é um *conjunto* de estados do AFND).
- O scanner inteiro é **um grande AFD** que volta a $s_0$ depois de cada token. Ex. `>=` : de `>` só para em `>=` se vier `=`; senão devolve `>` e faz **pushback** do caractere lido a mais.

### 3.4 JFlex — anatomia de um `.flex`
```code
// 1. código do usuário (imports)          ← copiado no topo do .java
%%
// 2. opções & macros (%class, %byaccj, DIGIT = [0-9] ...)
%%
// 3. regras :  padrão   { ação Java }      ← "casou a regra, executa"
```
**Duas regras que decidem tudo :**
1. **Casamento mais longo (maximal munch)** : `iff` vira `IDENT("iff")`, não `IF` + `f`; `==` vira um token só.
2. **Empate de tamanho → vence a regra declarada primeiro** : por isso `"if"` vem **antes** de `{id}`.
3. A regra `.` (qualquer coisa) vai **por último** — é o "catch-all" de erro léxico.

> **Dicas do Agustini** ([Aula05](../aula05.md)) : na prova, **não precisa** das macros DIGIT/LETTER/LineTerminator — o que vale (≈ 2,5 pts) é a **seção de regras**. E **saiba os terminais da gramática** : no JSON são `{ } [ ] : ,` `STRING` `NUMBER`.

### 3.5 Exemplo resolvido — scanner JSON (estilo questão 2 da P1)
Passo 1 — liste os terminais da gramática : `{` `}` `[` `]` `:` `,` `STRING` `NUMBER`.
Passo 2 — uma regra por terminal; brancos ignorados; `.` por último :
```code
%%
"{"                     { return ABRE_CHAVE; }
"}"                     { return FECHA_CHAVE; }
"["                     { return ABRE_COL; }
"]"                     { return FECHA_COL; }
":"                     { return DOIS_PONTOS; }
","                     { return VIRGULA; }
\"[^\"]*\"              { return STRING; }
-?[0-9]+(\.[0-9]+)?     { return NUMBER; }
[ \t\r\n]+              { /* ignora brancos */ }
.                       { System.err.println("Erro léxico: '" + yytext() + "' na linha " + (yyline+1)); }
```
Passo 3 — confira com o exemplo : `"price": 219.23,` → `STRING DOIS_PONTOS NUMBER VIRGULA`. ✔

## 4. Análise Sintática Descendente — passo a passo
### 4.1 A ideia
- Constrói a árvore **da raiz (S) para as folhas** (top-down), escolhendo a alternativa certa olhando **1 token de lookahead** (`la`).
- **ASDR** (analisador descendente recursivo) : **um método por não-terminal**. A pilha de chamadas de métodos **é** a pilha do autômato de pilha — "de graça".
- O analisador só diz **sim/não** + mensagens de erro. *"Se colocarem apenas 'ERRO' ou 'ERRO SINTÁTICO', vão perder 1,5"* ([Aula06](../aula06.md)) → a mensagem deve dizer **o que era esperado** e **a linha**.

### 4.2 Os padrões de tradução gramática → código
| Na gramática | No código |
|---|---|
| terminal `a` | `verifica(a);` *(Check)* |
| não-terminal `A` | `A();` |
| sequência `a B c` | `verifica(a); B(); verifica(c);` |
| alternativas `α \| β` | `if (la ∈ First(α)) {…} else if (la ∈ First(β)) {…} else erro(…);` |
| repetição `{ α }` / recursão à direita com ε | `while (la ∈ First(α)) { … }` |
| ε (vazio) | não faz nada — **mas só se `la ∈ Follow(A)`** |

```java
void scan()               { la = yylex(); }
void verifica(int tk)     { if (la == tk) scan(); else msgErro(nome(tk) + " esperado", linha); }
void parse()              { scan(); S(); verifica(EOF); }   // EOF: sem lixo depois do programa
```

### 4.3 Calculando First — algoritmo
1. Se `X` é terminal : `First(X) = {X}`.
2. Se existe `X → ε` : inclua `ε`.
3. Para `X → Y1 Y2 … Yn` : inclua `First(Y1) − {ε}`; **se `Y1` é anulável**, inclua também `First(Y2) − {ε}`; e assim por diante. Se **todos** são anuláveis, inclua `ε`.

### 4.4 Calculando Follow — algoritmo
1. `$` ∈ `Follow(S)` (símbolo inicial).
2. Para `A → α X β` : inclua `First(β) − {ε}` em `Follow(X)`.
3. Para `A → α X` , ou `A → α X β` com `β ⇒* ε` : inclua `Follow(A)` em `Follow(X)`.
4. **Repita** até nada mudar.

**Exemplo** (`S = A "c" | "d" . A = "a" A | ε .`) :
- `First(A) = {a, ε}` ; `First(S) = {a, c, d}` (o `c` entra porque `A` é anulável).
- `Follow(S) = {$}` ; `Follow(A) = {c}` (vem de `A c`).

### 4.5 Propriedade LL(1) — o teste
Para toda produção `A → α1 | α2 | … | αn` :
1. `First(αi) ∩ First(αj) = ∅` para todo `i ≠ j`;
2. se alguma `αi` é anulável : `First(αj) ∩ Follow(A) = ∅` para as outras.

**Quando é necessário?** Sempre que for escrever um ASDR (ou parser preditivo de tabela) **sem retrocesso**. Gramáticas com recursão à esquerda ou prefixos comuns **nunca** são LL(1).

### 4.6 As duas cirurgias
**Fatoração à esquerda** (prefixo comum) :
```code
A → α β1 | α β2 | γ        ⟹        A → α A' | γ
                                    A' → β1 | β2
```
**Eliminação de recursão à esquerda direta** (senão o ASDR entra em loop infinito) :
```code
A → A α | β                ⟹        A → β A'
                                    A' → α A' | ε
```
**Recursão indireta** (`A → B x`, `B → A z`) : ordene os NTs, **substitua** as referências "para trás" pelas produções do NT referenciado, e então elimine a recursão direta que aparecer.

### 4.7 Dangling else
- `Cmd → if E then Cmd RestoIf ; RestoIf → else Cmd | ε` → `First(else Cmd) ∩ Follow(RestoIf) = {else}` : **conflito LL(1)** e **ambiguidade** (duas árvores).
- Não sai por fatoração. Na prática : o parser escolhe a 1ª alternativa → **o else fica com o if mais próximo** (regra do C/Java).

### 4.8 Tratamento de erros
| Técnica | Como funciona | Custo | Uso |
|---|---|---|---|
| **Modo pânico** | aborta no 1º erro | nenhum | scripts, interpretadores simples |
| **Âncoras gerais** | cada método recebe `sux` (sucessores); em erro, pula tokens até `la ∈ sux` | tempo + espaço | ferramentas geradas |
| **Âncoras especiais** | sincroniza só em pontos seguros (início de comando: `if`, `while`…) | baixo, exige ajuste | compiladores feitos à mão |
- Heurística `errDist` : se menos de 3 tokens foram aceitos desde o último erro, não reporta (evita erros em cascata).

## 5. Exemplo resolvido completo — o JSON da P1 2014/1
```code
JSON     → ARRAY | OBJECT
OBJECT   → "{" MEMBERS "}"
MEMBERS  → STRING ":" VALUE | STRING ":" VALUE "," MEMBERS
ARRAY    → "[" ELEMENTS "]"
ELEMENTS → ELEMENTS "," VALUE | VALUE
VALUE    → STRING | NUMBER | OBJECT | ARRAY
```
**Passo 1 — terminais, não-terminais, símbolo inicial.**
- T = `{ } [ ] : , STRING NUMBER` ; N = `JSON OBJECT MEMBERS ARRAY ELEMENTS VALUE` ; S = `JSON`.
- "Como saber se gera o exemplo?" → mostrar uma **derivação** (ou árvore) de `S` até a sentença.

**Passo 2 — é LL(1)? Não :**
- `MEMBERS` : as duas alternativas começam com `STRING` → **prefixo comum** → fatorar.
- `ELEMENTS` : **recursão à esquerda** → eliminar.

**Passo 3 — gramática LL(1) :**
```code
JSON      → ARRAY | OBJECT                         First: {[}  {{}
OBJECT    → "{" MEMBERS "}"
MEMBERS   → STRING ":" VALUE RestoM
RestoM    → "," MEMBERS | ε                        Follow(RestoM) = { } }
ARRAY     → "[" ELEMENTS "]"
ELEMENTS  → VALUE RestoE
RestoE    → "," VALUE RestoE | ε                    Follow(RestoE) = { ] }
VALUE     → STRING | NUMBER | OBJECT | ARRAY       First disjuntos
```
**Passo 4 — o ASDR** (um método por NT; funções auxiliares da prova: `yylex`, `verifica`, `msgErro`) :
```java
public class Parser {
    private int la;            // token de lookahead
    private Yylex lexer;

    void scan() { la = lexer.yylex(); }

    void verifica(int esperado) {
        if (la == esperado) scan();
        else msgErro(nome(esperado) + " esperado, encontrado " + nome(la), lexer.linha());
    }

    void json() {
        if      (la == ABRE_COL)   array();
        else if (la == ABRE_CHAVE) object();
        else msgErro("JSON deve iniciar com [ ou {", lexer.linha());
    }
    void object()   { verifica(ABRE_CHAVE); members(); verifica(FECHA_CHAVE); }
    void members()  { verifica(STRING); verifica(DOIS_PONTOS); value(); restoM(); }
    void restoM()   { if (la == VIRGULA) { scan(); members(); } /* ε : la deve ser } */ }
    void array()    { verifica(ABRE_COL); elements(); verifica(FECHA_COL); }
    void elements() { value(); while (la == VIRGULA) { scan(); value(); } }   // RestoE como laço
    void value() {
        switch (la) {
            case STRING: case NUMBER: scan(); break;
            case ABRE_CHAVE: object(); break;
            case ABRE_COL:   array();  break;
            default: msgErro("valor esperado (string, número, { ou [)", lexer.linha());
        }
    }
    public static void main(String[] args) throws Exception {
        Parser p = new Parser();
        p.lexer = new Yylex(new java.io.FileReader(args[0]));
        p.scan(); p.json(); p.verifica(EOF);
        System.out.println("JSON sintaticamente correto");
    }
}
```
**Passo 5 — questões de "que erro aparece" (raciocine seguindo as chamadas) :**
- **Apagar a vírgula** depois de `"price": 219.23` → `restoM()` vê `STRING` (não é `,`), toma ε e retorna; `object()` executa `verifica(FECHA_CHAVE)` e falha : **"} esperado, encontrado STRING"**, em `object()`.
- **Apagar a linha inteira** de `"tags"` → continua válido (`, "stock": …` segue o padrão) : **sem erro**.
- **`"tags": [ ],`** → `elements()` chama `value()` com `la = ]` : **"valor esperado"**, em `value()` — a gramática **não aceita arranjo vazio**.

## 7. Gabarito
<details><summary>A1</summary>

a) `0[xX][0-9a-fA-F]+` — AFD : `s0 -0-> s1 -x|X-> s2 -hex-> s3` (final, laço em `hex`).
b) `\"([^\"\\\n]|\\.)*\"` — dentro das aspas : qualquer caractere que não seja `"`, `\` ou fim de linha, **ou** uma barra seguida de qualquer caractere.
c) `[0-9]+\.[0-9]*([eE][+-]?[0-9]+)?|\.[0-9]+([eE][+-]?[0-9]+)?`
d) `"//".*` — o `.` não casa `\n`, então para no fim da linha.
</details>

<details><summary>A2</summary>

a) `(id - id) - id` → `(8-4)-2 = 2` (correta, associativa à esquerda); `id - (id - id)` → `8-(4-2) = 6`.
b) `E → E - T | T` ; `T → T / F | F` ; `F → id`.
c) **lm** : `E ⇒ E - T ⇒ T - T ⇒ F - T ⇒ id - T ⇒ id - T / F ⇒ id - F / F ⇒ id - id / F ⇒ id - id / id`
**rm** : `E ⇒ E - T ⇒ E - T / F ⇒ E - T / id ⇒ E - F / id ⇒ E - id / id ⇒ T - id / id ⇒ F - id / id ⇒ id - id / id`
</details>

<details><summary>A3</summary>

```code
%%
";".*                          { /* comentário */ }
"["[a-zA-Z_][a-zA-Z0-9_]*"]"   { return SECAO; }
"true"                         { return TRUE; }
"false"                        { return FALSE; }
[a-zA-Z_][a-zA-Z0-9_]*         { return IDENT; }
```

`true`/`false` devem vir **antes** de `IDENT` : com o mesmo tamanho de casamento, vence a regra declarada primeiro. `trueValor` vira `IDENT` — o casamento mais longo (9 caracteres) vence `true` (4).
</details>

<details><summary>A4</summary>

| NT | First | Follow |
|---|---|---|
| Cmd | `id, if, {` | `$, id, if, {, }` |
| Resto | `=, (` | `$, id, if, {, }` |
| Lista | `id, if, {, ε` | `}` |
| Exp | `id, num` | `), ;` |

- `Follow(Cmd)` : `$` (inicial) ∪ `First(Lista) − ε` (de `Cmd Lista`) ∪ `Follow(Lista)` (Lista anulável) = `{$, id, if, {, }}`.
